# Patrones del showcase: inspiración con marca propia

Consulta de fuentes públicas: 7 de septiembre de 2026. La selección procede de
los favoritos del showcase de Docusaurus. Se revisó la estructura publicada de
las páginas enlazadas; no se realizó una comparación visual pixel a pixel ni una
auditoría de accesibilidad de esos sitios. Revalidar sus patrones al utilizarlos.

| Referencia | Patrón observado | Aplicación a esta guía |
| --- | --- | --- |
| Ionic Docs | Entradas a instalación, componentes y temas; navegación agrupada y versión visible | Separar el recorrido por lo que el lector está haciendo —empezar, crear, recursos, evaluación, submissions, referencia— y dejar la versión a la vista |
| Refine Docs | Inicio rápido, tutoriales, conceptos y referencia diferenciados | No mezclar conceptos, procedimiento y troubleshooting en una sola página, que es de donde se parte |
| React Native Docs | Introducción orientada al lector y rutas de aprendizaje | Que cada índice de sección diga qué se consigue ahí y por dónde se sigue |

Estas aplicaciones son decisiones de este paquete, no recomendaciones hechas por
los autores de esos sitios. No copiar su CSS, assets, textos, componentes ni
paletas. No presentar su inclusión en el showcase como una garantía de
cumplimiento o aval de esta skill.

## Procedimiento cuando se diseñe el portal

Seleccionar dos o tres páginas pertinentes, no recopilar decenas de ejemplos.
Con navegador disponible, inspeccionar portada, artículo y referencia en desktop
y móvil. Registrar URL, patrón, problema que resuelve y adaptación a Captia.
No afirmar que se observó una interacción a partir de HTML o una miniatura.

Redactar un breve esquema funcional con los contenidos que hay de verdad. Aquí
los tokens no hay que aplicarlos después: ya están, y son los del manual de
captia.ai. Si una idea contradice la marca, la accesibilidad o el alcance,
descartarla. No hacer una clonación visual.
